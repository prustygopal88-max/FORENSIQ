# FORENSIQ Live Demonstration Guide

This guide describes the exact steps to demonstrate **FORENSIQ** to evaluators and professors.

---

## Pre-requisites & Setup
1. Launch Backend:
   ```bash
   # From project root
   run_backend.bat
   # Or manually:
   cd backend
   python -m uvicorn app.main:app --reload --port 8000
   ```
2. Launch Frontend:
   ```bash
   # In a separate terminal from project root
   run_frontend.bat
   # Or manually:
   cd frontend
   npm run dev
   ```
3. Open browser at `http://localhost:5173`.

---

## DEMO 1: Live Authentication Anomaly & Dynamic Temporal Filtering

### Step 1: Open Live Auth Demo
- Click **"Live Auth Demo"** in the sidebar.
- Note that the default demo account is **Gopal** (or you can click "Configure Account" to create a custom name like your professor's or student's name).

### Step 2: Trigger Real Failed Login Events
- Click the red button: **[ Simulate Wrong Password (Record FAILED) ]** 2 to 3 times (or intentionally type a wrong password in the password field and click Enter).
- Observe:
  - Real HTTP 401 response is generated by FastAPI.
  - The live counter immediately increments (`Failed Logins Recorded: 3`).
  - The real-time SQLite Event Stream updates dynamically showing `FAILED_LOGIN` events (e.g. `EVT-AUTH-0010`, `EVT-AUTH-0011`, `EVT-AUTH-0012`).

### Step 3: Trigger Real Successful Login
- Click the cyan button: **[ Enter Correct Password (Authenticate) ]** with `password123`.
- Observe:
  - Real HTTP 200 response is generated.
  - Successful login event (`SUCCESSFUL_LOGIN`) is stored in SQLite (e.g. `EVT-AUTH-0013`).
  - Active session updates to `Gopal`.

### Step 4: Ask Natural Language Question
- Click **"Investigate this Auth Sequence in FORENSIQ"** or navigate to the **Investigate** tab.
- Click the first prompt chip or enter:
  ```text
  Show me failed login attempts before the successful login.
  ```
- Click **[ INVESTIGATE ]**.

### Step 5: Verify the 4 Core Output Sections
1. **Query Interpretation:**
   - Intent: `Authentication Investigation`
   - Target Event: `Authentication (Status: FAILED)`
   - Temporal Relation: `BEFORE`
   - Reference Landmark: `successful_login`
2. **Structured Forensic Query:**
   - Formatted JSON query object matching the NLP interpretation.
   - Shows the resolved SQLite landmark event (`EVT-AUTH-0013`).
3. **Evidence Results:**
   - Displays the exact failed login events generated in Step 2.
   - Click any row to inspect full JSON metadata.
4. **Explainable Reasoning:**
   - Step-by-step verification checklist proving event type match, status match, temporal precedence, and negative time delta (e.g. `-21s`, `-38s`).
5. **Timeline View:**
   - Chronological flow leading directly to the landmark reference point.

### Step 6: Dynamic Temporal Window Demonstration
- Enter or click:
  ```text
  Show failed login attempts within 5 minutes before the successful login.
  ```
- Observe how the temporal engine computes the window bounds `[T_ref - 5m, T_ref]` dynamically.

## DEMO 2: USB Peripheral & File Exfiltration Simulation

### Step 1: Open USB Investigation
- Click **"USB Investigation"** in the sidebar.

### Step 2: Execute Sequence
- Option A (Step-by-Step): Click **Simulate USB Connect** -> **Simulate File Access** -> **Simulate File Copy** -> **Simulate USB Remove**.
- Option B (1-Click): Click **[ Execute Full 4-Step Incident Sequence ]**.
- Observe the real-time peripheral event stream populated in SQLite with `USB_CONNECTED`, `FILE_ACCESS`, `FILE_COPY`, and `USB_REMOVED`.

### Step 3: Run Natural Language USB Query
- In the USB Inquiry deck, click **[ Execute USB Temporal Query ]** or enter in the Investigate tab:
  ```text
  What files were copied to USB after it was connected?
  ```
- Observe:
  - Correctly extracts target file: `Financial_Report.xlsx`.
  - Proves destination device: `USB-001`.
  - Explains that the USB connection was verified prior to file transfer.

## DEMO 3: Forensic Dossiers & Official Report Generation

### Step 1: Generate Formal Report
- In the Investigate tab, click **[ Generate Official Report ]**.
- Inspect the generated confidential forensic summary.
- Click **Copy Report** (copies clean Markdown) or **Print / PDF** (opens browser print view).

### Step 2: Operational Dashboard & Cases
- Open **Dashboard** to show live real-time statistics calculated directly from SQLite.
- Open **Cases** to view active forensic files (`CAS-2026-001`, `CAS-2026-002`) and create a new case dossier.
- Open **Explainability** to show the interactive 6-step pipeline diagram.
